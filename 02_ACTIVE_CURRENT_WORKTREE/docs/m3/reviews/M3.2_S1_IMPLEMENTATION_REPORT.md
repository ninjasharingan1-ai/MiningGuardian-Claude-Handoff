## Contracts implemented

`contracts.py` defines versioned, extra-field-forbidding Pydantic shapes for state validity and snapshot completeness, structured support checks, all six uncertainty dimensions, evidence dispositions and references, field-specific evidence requirements and completeness, first-class conflicts, separately labeled last-known context, estimated fields, requested-field snapshots, semantic content identity, production metadata, and `EstimatedState`. New authoritative timestamps must be aware and normalize to UTC. Canonical source observation and receipt times remain separate. Non-finite canonical values are rejected.

Contract validation enforces null current values for `UNKNOWN`/`INVALID`, non-null values and supporting observation identities for `VALID`/`DEGRADED`, a positive failure reason for `INVALID`, a versioned degradation rule for `DEGRADED`, all declared required evidence for `VALID`, explicit confidence/uncertainty distinctions, complete and nonduplicated snapshot inventories, consistent reference times, and summary/list agreement. A conflict cannot silently select a participant without a versioned rule. Source identity may remain null. Zero is a valid supported value. Production `estimated_at` is distinct from state reference time.

These are **contract shapes and invariants only**. S1 does not compute a state estimate, select evidence, query storage, generate a content digest, verify a claimed input digest against storage, persist derived state, fetch an economic provider, or actuate anything. Those responsibilities belong to separately authorized later slices.

## Final narrow remediation of IR-S1-02-R1 — 2026-09-21

The separate independent remediation recheck found IR-S1-02 only partially

### Root cause and exact invariant

`StateConflict.participants_preserved()` checked the presence of a versioned rule
and reason but did not require a declared outcome for RESOLVED value disagreement.
It now additionally enforces:

```text
kind == VALUE_DISAGREEMENT and resolution_status == RESOLVED
    => selected_evidence_ids is nonempty OR rejected_evidence_ids is nonempty
```

Existing checks still require selected/rejected IDs to belong to the conflict's
participants and prohibit overlap. Existing UNRESOLVED behavior remains intact:
comparable disagreement cannot accompany a VALID or DEGRADED current value;
UNKNOWN and explained INVALID remain representable. Nested field construction
validates the conflict, so raw dictionaries cannot evade the added invariant.

This is structural validation. It does not execute or authenticate the named
rule, choose a winner, require exactly one winner, or introduce a source policy.
Selected-only, rejected-only, and multiple-selected metadata are permitted by
the narrow minimum-outcome requirement; no new exhaustive-partition rule is
invented. Runtime eligibility and any future rule's acceptance remain separate.
