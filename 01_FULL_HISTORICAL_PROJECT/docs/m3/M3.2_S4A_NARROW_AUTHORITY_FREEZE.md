## Normative Rules

### 1. S3 Binding

S4-A MUST consume temporal eligibility, subject/workload/algorithm identity, continuity segment membership, and conflict/comparability status only from authoritative S3 semantic outputs or immutable/reconstructible references to those outputs.

Such references MUST preserve enough identity to establish canonical observation identity, relevant S3 artifact/reference identity, applicable S3 method/configuration/version identity, and coherence between observations and S3 dispositions.

Caller-authored free-form comparability, segment identity, or temporal eligibility MUST NOT be treated as authority.

Exact Python wrapper or class representation remains implementation-local.

### 2. Value-Kind Applicability

Generic S4-A arithmetic/descriptive methods `mean`, `median`, `min`, `max`, `delta`, `counter_rate`, and `historical_endpoint_slope` MUST operate only on finite numeric values.

`missing_fraction` MUST produce a finite numeric dimensionless ratio from explicit opportunity semantics defined below.

`latest_eligible_value` MAY preserve a field-contract-authorized non-numeric scalar value when no value ordering, value comparison, or arithmetic is required. Chronological/temporal ordering for latest remains required.

S4-A MUST NOT invent arbitrary JSON ordering or comparison semantics.

### 3. Unit Conversion

S4-A MUST NOT execute unit-conversion arithmetic.

Evidence requiring conversion before method computation MUST NOT contribute as method support unless an authority-approved compatible value already exists and retains the applicable conversion identity/version/provenance.

A declared conversion MUST NOT by itself make evidence VALID.

S4-A MUST NOT invent conversion formulas, conversion registries, implicit unit conversion, or mutable conversion aliases.

### 4. Output Unit Semantics

Semantic output unit meaning is distinct from serialization spelling.

`latest`, `mean`, `median`, `min`, `max`, and `delta` produce the field's declared value-unit semantics.

`counter_rate` produces counter quantity unit / elapsed source-time unit.

`historical_endpoint_slope` produces value quantity unit / elapsed historical-time unit.

`missing_fraction` is dimensionless.

A field contract MUST declare the applicable semantic output-unit meaning before a derived rate/slope result can be reported as a field value.

Exact serialization strings such as `count/s` are NOT frozen by this document.

### 5. Analytical Input Set / Cross-Stream Behavior

S4-A MUST compute one method over one declared field request and one authoritative comparable analytical input set.

S4-A MUST NOT resolve disagreement through latest-provider wins, preferred source, averaging as conflict resolution, min/max as conflict resolution, voting, or hidden provider ranking.

Delta, counter rate, and historical slope MUST NOT use endpoints from different authoritative S3 continuity segments.

Multiple observations MAY participate only when accepted S3/field authority establishes compatibility for subject, quantity, unit, effective-time interpretation, and conflict disposition.

Unresolved disagreement MUST NOT be converted into a method result by S4-A.

### 6. Missing Fraction

`missing_fraction` MUST use missing required opportunities / explicit expected opportunities.

Expected opportunities MUST be explicit and positive.

Observed qualifying opportunities MUST be explicit, or derivable only where accepted authority establishes a one-to-one observation/opportunity relation.

S4-A MUST NOT infer cadence, schedule, absent acquisition events, or duplicate-opportunity identity from raw row count alone.

If expected-opportunity semantics or qualifying-opportunity semantics cannot be established, S4-A MUST NOT produce a numeric `missing_fraction` result.

Final field assessment such as UNKNOWN belongs to the later assessment boundary; this S4-A rule does NOT assign final field validity.

Exact opportunity-manifest representation remains implementation-local.

### 7. Method Configuration Identity

S4-A method configuration identity MUST include `method_name`, `method_version`, `field_contract_id`, `field_contract_version`, and every explicit method-specific semantic parameter not already fixed by those versions.

`configuration_sha256` MUST be computed over a deterministic canonical, schema-versioned semantic projection of that method configuration.

Exact configuration MUST remain recoverable. Digest-only configuration retention is insufficient.

The following are authoritative semantic inputs but are NOT automatically duplicated into method configuration unless they are explicit method parameters: input evidence identity, S3 semantic references, requested scope, `state_reference_time`, selected/excluded dispositions, and semantic result values.

Those inputs participate in later deterministic semantic artifact identity according to existing S4/ADR authority.

S4-A MUST NOT thereby become responsible for constructing the final `semantic_content_id` if that responsibility belongs to a later S4 slice.

Production metadata remains outside semantic content identity.
