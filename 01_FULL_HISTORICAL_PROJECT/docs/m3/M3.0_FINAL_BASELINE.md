## 7. Frozen RewardTarget contract

Accepted objective types:

```text
MINIMUM
BAND
```

Not accepted as a RewardTarget type:

```text
MAXIMIZE
```

`MAXIMIZE` remains a strategic optimization objective.

RewardTarget lifecycle:

```text
DRAFT
ACTIVE
EXPIRED
RETIRED
SUPERSEDED
```

Only an `ACTIVE` target may be consumed for runtime target tracking.

## 8. Frozen controller-state contract

```text
NO_ACTIVE_TARGET
    active_reward_target_id = null
    latest_assessment_id = null
    target-seeking pressure = false

ASSESSMENT_UNAVAILABLE
    active_reward_target_id required
    latest_assessment_id = null
    target-seeking pressure = false

ACTIVE
    active_reward_target_id required
    latest_assessment_id required
```

These states are mutually exclusive.

No fake/sentinel target IDs are accepted.

## 9. Frozen assessment contract

Assessment quality:

```text
VALID
UNCERTAIN
STALE
INVALID
```

Performance state when VALID:

```text
BELOW_TARGET
WITHIN_TARGET_BAND
ABOVE_TARGET
```

Attainability:

```text
ATTAINABLE
UNREACHABLE_SAFELY
UNKNOWN
```

Required/nullability invariants:

```text
assessment_quality = VALID
    current_reward_state required
    signed_target_gap required
    performance_state required

assessment_quality != VALID
    signed_target_gap = null
    performance_state = null
    attainability = UNKNOWN
    decision_evaluation_required = false
```

## 10. Frozen signed-gap mathematics

Sign convention:

```text
positive = unmet shortfall
zero     = acceptable target region
negative = above acceptable target region
```

`MINIMUM`:

```text
current < target_value
    gap = target_value - current
    performance_state = BELOW_TARGET

current == target_value
    gap = 0
    performance_state = WITHIN_TARGET_BAND

current > target_value
    gap = target_value - current
    performance_state = ABOVE_TARGET
```

`BAND [lower, upper]`:

```text
current < lower
    gap = lower - current
    performance_state = BELOW_TARGET

lower <= current <= upper
    gap = 0
    performance_state = WITHIN_TARGET_BAND

current > upper
    gap = upper - current
    performance_state = ABOVE_TARGET
```

## 11. Reward semantics

`RewardContract` is first-class and versioned.

It defines:

- economic metric;
- unit;
- gross/credited-work basis;
- pool payout/accounting semantics;
- included realized costs;
- excluded decision penalties;
- missing-data behavior;
- maturity;
- calculation/version semantics.

Frozen separation:

```text
realized economic Reward
≠
ADR-0006 probabilistic Risk / predicted ActionCost / Uncertainty
```

Realized transition/restart/switching/operating costs may be included only if the RewardContract explicitly defines them.

## 12. Time/window semantics

These remain distinct:

```text
Control Evaluation Interval
Statistical Estimation Horizon
Prediction Horizon
Pool Accounting Window
Reward Evaluation Window
Outcome Observation Window
Reward Attribution Window
Network Block Interval
Cooldown / Dwell Interval
```

No implementation may collapse these merely because their durations happen to match.

## 13. Outcome and attribution

Accepted Outcome scopes:

```text
PERFORMANCE_WINDOW
ACTION_ATTRIBUTED
```

`PERFORMANCE_WINDOW` may exist with no Decision, Action, or Execution.

`ACTION_ATTRIBUTED` requires applicable action/execution identity plus an auditable reference basis before Learning/Promotion use.

Prediction must never be copied into Outcome.

## 14. Action / execution boundary

Accepted runtime path:

```text
DecisionResult
→ ActionRequest
→ Capability Gate
→ Execution Safety Gate
→ Freshness Gate
→ Stability / Rate Gate
→ Rollback Gate
→ Human Approval Gate when required
→ ExecutionAuthorization
→ Execution Adapter
→ ExecutionRecord
→ RollbackRecord when applicable
```

`ExecutionAuthorization` is not M2 Policy.

Safe Control may not re-score, re-rank, or substitute a candidate.

If runtime state invalidates the selected Decision:

```text
REEVALUATION_REQUIRED
→ return to M2 Decision Engine
```

## 15. Learning / promotion boundary

Accepted path:

```text
Outcome / Reward / PredictionError
→ LearningArtifact
→ UpdateProposal
→ Offline / Replay Verification
→ PromotionDecision
→ Active Version
```

Learning cannot directly mutate:

- active model;
- safety policy;
- M2 Policy;
- RewardTarget;
- production knowledge;
- active controller.

Frozen distinction:

```text
M2 DecisionEvaluationRepository
≠
M3 Runtime Evidence Persistence
```

M3 Runtime Evidence Persistence is a logical owner, not yet a selected storage technology.

It may persist applicable:

```text
runtime observations/events

```

M3 reconstruction must preserve facts/provenance and must not re-run cognition.

## 17. Safety / continuity baseline

Frozen priority:

```text
Hardware Safety
> Mining Continuity
> Evidence Quality / Observability
> Constraint Compliance
> Net Effective Reward Objective
> Energy Efficiency
> Exploration / Learning
```

Accepted anti-churn concepts include applicable:

```text
deadband
hysteresis
minimum dwell
cooldown
rate limits
minimum expected improvement
switching penalty
restart budget
```

Restart is a high-cost intervention and is not a normal tuning primitive.

## 18. Runtime strategic reasoning boundary

Runtime LLM/strategic reasoning is future advisory intelligence only.

It may propose interpretations, investigations, experiments, and strategy.

It may not:

- become authoritative raw evidence;
- bypass M2 decision ownership;
- authorize execution;
- directly actuate GPU/miner/pool/OS controls;
- rewrite historical evidence.

## 19. Accepted non-blocking notes

### NB-01

Implementation handoffs should instantiate deterministic tests for controller-state and assessment-quality invariants.

### NB-02

`current_reward_uncertainty` remains architecture-level optional and may be strengthened by a statistical-method contract.

### NB-03

Target urgency may trigger reevaluation only. It cannot silently alter ADR-0006 scoring.
