# M3.0 Remediation v0.4

Authorized after `M3.0 Architecture Review #3 — Read Only Freeze Audit v0.3`.

## Review #3 HIGH findings closed

1. `MINIMUM` and `BAND` now have frozen deterministic `signed_target_gap` and `performance_state` semantics.
2. `NO_ACTIVE_TARGET` no longer requires fake RewardTarget IDs or target gaps. Controller availability is represented by a separate `RewardTargetControllerState`.

## Reward-target ontology split

The previous overloaded runtime target state is replaced conceptually by:

```text
RewardTarget.lifecycle_status
RewardTargetControllerState.controller_status
RewardTargetAssessment.assessment_quality
RewardTargetAssessment.performance_state
RewardTargetAssessment.signed_target_gap
RewardTargetAssessment.attainability
```

These concepts are independent and must not be collapsed.

## Frozen signed-gap convention

```text
positive  = unmet shortfall
zero      = acceptable target region
negative  = above acceptable target region
```

Exact MINIMUM/BAND formulas are now canonical contract semantics.

## Review #3 MEDIUM findings closed

3. RewardTarget definition uses explicit `lifecycle_status = DRAFT | ACTIVE | EXPIRED | RETIRED | SUPERSEDED`.
4. Runtime evidence now carries `authorization_id`, authorization status/timestamps, and `rollback_id` when applicable.
5. Correlation chain now includes RewardTarget, controller state, assessment, RewardEvaluationWindow, ExecutionAuthorization, RollbackRecord, UpdateProposal, and PromotionDecision.

## Scope

This remains an architecture/contract remediation only. No database technology, ML algorithm, controller algorithm, or live execution implementation is selected.

Next step: Architecture Review #4 — narrow contract-freeze verification.
