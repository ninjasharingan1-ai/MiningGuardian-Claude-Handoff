# M3.2 S4A R4 - Historical Arithmetic Authority Clarification

## Status

`R4_HISTORICAL_ARITHMETIC_AUTHORITY_CLARIFIED`

ACCEPTED NORMATIVE CLARIFICATION.

This clarification authorizes only the R4 execution semantics for:

- `within_segment_delta`;
- `source_time_counter_rate`;
- `historical_endpoint_slope`.

It does not alter R2 historical support binding, S3 admission, identity,
continuity, conflict, or evidence-selection semantics.

It does not authorize `missing_fraction`.

---

## 1. R2 remains the sole support authority

R4 MUST NOT select, rank, merge, sort, repair, or manufacture historical
support.

R4 MUST obtain its analytical support only by calling the accepted
`bind_method_support(...)` boundary.

If that boundary returns `MethodNoResult`, R4 MUST return that outcome
unchanged.

If the boundary returns `AuthoritativeAnalyticalSet`, R4 MAY execute only
when:

- `support_view == "HISTORICAL"`;
- `continuity_segment_id` is present;
- the configured method is one of the three R4 methods named above.

Caller-supplied analytical support is not authorized.

R4 MUST NOT accept a caller-provided continuity segment, endpoint pair,
observation subset, evidence ranking, or free-form exclusion reason.

---

## 2. Authoritative historical order is frozen

`AuthoritativeAnalyticalSet.support_observation_ids` is the sole R4
historical observation order.

R4 MUST preserve that order exactly.

R4 MUST NOT reorder support by:

- UUID;
- caller order;
- provider identity;
- stream identity;
- raw value;
- ingestion recency;
- source-time recency;
- minimum or maximum timestamp;
- any hidden ranking rule.

For endpoint arithmetic:

- the first endpoint is the first authoritative support observation;
- the last endpoint is the last authoritative support observation.

Intermediate authoritative support remains part of the analytical set.

Endpoint arithmetic MUST NOT silently change upstream evidence accounting.

---

## 3. Minimum arithmetic cardinality

All three R4 methods require at least two authoritative historical support
observations.

When the bound analytical set contains fewer than two support observations,
R4 MUST return:

`INSUFFICIENT_CARDINALITY`

Every observation that had role `USED` in the bound analytical set becomes
`EXCLUDED` in that no-result outcome with the closed reason:

`method:insufficient_cardinality`

Already-excluded observations retain their accepted upstream exclusion
reasons.

R4 MUST NOT fabricate a second endpoint.

---

## 4. Exact numeric input domain

R4 arithmetic accepts only finite numeric scalar endpoint values:

- integer;
- finite floating-point value.

Boolean values are not numeric for R4.

Strings, containers, null-like execution-layer values, and unsupported
objects are not arithmetic values.

Finite floating-point values MUST be converted from their exact binary
representation using their exact integer ratio.

R4 MUST NOT round through decimal text.

R4 MUST NOT coerce strings or booleans into numbers.

Unsupported arithmetic value kinds use the existing method-layer error
boundary and MUST NOT be silently converted.

---

## 5. Exact result arithmetic

All successful R4 arithmetic results MUST use `ExactNumber`.

Intermediate arithmetic MUST use exact rational arithmetic.

No R4 method may use binary floating-point accumulation or rounded
`total_seconds()` arithmetic to construct its final mathematical value.

Arithmetic zero is canonical exact zero.

R4 does not preserve signed floating-point zero in derived arithmetic
results.

---

## 6. Canonical endpoint value delta

For authoritative endpoint values:

- `first_value` = value of the first authoritative support observation;
- `last_value` = value of the last authoritative support observation.

The canonical endpoint delta is:

`last_value - first_value`

The subtraction is exact.

R4 MUST NOT:

- take absolute value;
- reorder endpoints to force a positive delta;
- clamp negative results;
- infer counter rollover;
- infer counter reset;
- unwrap a counter;
- interpolate missing values.

A negative endpoint delta remains a negative endpoint delta.

---

## 7. within_segment_delta

`within_segment_delta` returns the exact canonical endpoint value delta.

It uses no elapsed-time denominator.

Its successful unit semantics are:

- `kind = "FIELD_VALUE"`;
- `value_unit = field_contract.output_unit`;
- `declared_result_unit = field_contract.output_unit`.

If `field_contract.output_unit` is absent, R4 MUST return:

`RESULT_UNIT_SEMANTICS_UNDECLARED`

with the closed method-layer exclusion reason:

`method:result_unit_semantics_undeclared`

No unit conversion is authorized in R4.

---

## 8. Canonical exact elapsed seconds

Whenever R4 requires an elapsed duration, the duration MUST be represented
as exact seconds.

For two timezone-aware datetimes, the exact elapsed duration is derived from
the datetime difference using integer day, second, and microsecond
components.

Conceptually:

`exact_seconds = total_microseconds / 1_000_000`

No floating-point `total_seconds()` result may define the arithmetic
denominator.

R4 requires a strictly positive elapsed duration.

A missing endpoint clock, equal endpoint clock, or non-positive endpoint
duration does not authorize rate or slope arithmetic.

Those cases return:

`NO_POSITIVE_ELAPSED_INTERVAL`

with the closed method-layer exclusion reason:

`method:no_positive_elapsed_interval`

R4 MUST NOT reverse endpoints merely to obtain a positive interval.

---

## 9. source_time_counter_rate

`source_time_counter_rate` uses the canonical endpoint value delta as its
numerator.

Its denominator is the exact elapsed SOURCE OBSERVATION TIME between the
same authoritative endpoints.

For this method only:

- first time = first endpoint `observation_time`;
- last time = last endpoint `observation_time`.

`source_time_counter_rate` MUST use source observation time regardless of
the field contract's configured historical temporal basis.

It MUST NOT substitute ingestion time when source observation time is
missing.

It MUST NOT use guardian receipt time as a fallback.

The successful result is:

`endpoint_delta / exact_source_elapsed_seconds`

Its successful unit semantics are:

- `kind = "COUNTER_QUANTITY_PER_SOURCE_TIME"`;
- `numerator_unit = field_contract.output_unit`;
- `denominator_time_basis = "SOURCE_TIME"`;
- `declared_result_unit = None`.

The numeric denominator scale is canonical exact seconds.

If `field_contract.output_unit` is absent, R4 returns
`RESULT_UNIT_SEMANTICS_UNDECLARED`.

No synthesized display-unit string is authorized.

No counter rollover, reset, wraparound, monotonicity correction, or hidden
counter normalization is authorized.

---

## 10. historical_endpoint_slope

`historical_endpoint_slope` is an endpoint slope.

It is not:

- linear regression;
- least-squares slope;
- average pairwise slope;
- interpolation;
- smoothing;
- trend fitting.

Its numerator is the canonical endpoint value delta.

Its denominator is the exact elapsed HISTORICAL TIME between the same
authoritative endpoints.

Historical time is selected according to the accepted
`field_contract.temporal_basis` through the existing selected-time
semantics:

- `SOURCE_OBSERVATION_TIME` uses `observation_time`;
- `GUARDIAN_RECEIPT_TIME` uses `ingestion_time`.

The successful result is:

`endpoint_delta / exact_historical_elapsed_seconds`

Its successful unit semantics are:

- `kind = "VALUE_QUANTITY_PER_HISTORICAL_TIME"`;
- `numerator_unit = field_contract.output_unit`;
- `denominator_time_basis = "HISTORICAL_TIME"`;
- `declared_result_unit = None`.

The numeric denominator scale is canonical exact seconds.

If the selected historical clock cannot establish a strictly positive
endpoint interval, R4 returns `NO_POSITIVE_ELAPSED_INTERVAL`.

If `field_contract.output_unit` is absent, R4 returns
`RESULT_UNIT_SEMANTICS_UNDECLARED`.

No synthesized display-unit string is authorized.

---

## 11. Evidence-use accounting for successful R4 results

A successful R4 result preserves the complete accepted
`AuthoritativeAnalyticalSet.evidence_use` accounting.

R4 MUST NOT mark intermediate same-segment support as excluded merely
because endpoint arithmetic uses the first and last values.

Those observations remain authoritative support for the accepted historical
analytical set and continuity segment.

No evidence-use entry may disappear.

No caller-generated reason is authorized.

---

## 12. Evidence-use accounting for R4 arithmetic no-result

When R4 itself produces one of these arithmetic-stage ordinary no-results:

- `INSUFFICIENT_CARDINALITY`;
- `NO_POSITIVE_ELAPSED_INTERVAL`;
- `RESULT_UNIT_SEMANTICS_UNDECLARED`;

all observations that were authoritative `USED` support MUST become
`EXCLUDED` with the corresponding closed R4 method-layer reason.

Already-excluded observations preserve their existing upstream reason.

R4 MUST NOT overwrite a more specific accepted upstream exclusion reason.

The resulting evidence-use accounting MUST remain complete and
deterministic.

---

## 13. No unit conversion

R4 MUST NOT execute any declared or inferred unit conversion.

Unit compatibility and conversion authorization remain upstream support
concerns.

If the accepted binder has already produced `MethodNoResult`, R4 propagates
it unchanged.

R4 MUST NOT reinterpret excluded evidence in order to make arithmetic
possible.

---

## 14. No hidden endpoint recovery

If authoritative historical support does not provide a valid arithmetic
endpoint condition, R4 MUST NOT recover one by:

- selecting a different segment;
- dropping an endpoint;
- choosing an interior pair;
- sorting by another clock;
- crossing a continuity boundary;
- merging streams;
- choosing one side of a conflict;
- using current-only evidence;
- inventing missing time;
- changing the configured temporal basis.

No-result is preferred over hidden recovery.

---

## 15. Determinism

Equivalent authoritative inputs MUST produce equivalent R4 outcomes.

R4 arithmetic contains:

- no wall-clock dependency;
- no randomness;
- no provider ranking;
- no caller-defined ordering;
- no floating-point accumulation;
- no hidden unit conversion;
- no hidden continuity selection;
- no hidden endpoint selection.

Exact rational arithmetic and authoritative support order define the
successful result.

---

## 16. Execution surface

R4 may introduce one private execution boundary for these three methods.

The boundary MUST accept only:

- `configuration`;
- `authoritative_input`.

It MUST obtain support internally through `bind_method_support(...)`.

It MUST NOT accept caller-provided `AuthoritativeAnalyticalSet`.

R4 does not authorize a public `compute_method`.

R4 private execution MUST NOT be exported through `__all__`.

R3 execution semantics and the accepted private R3 execution surface remain
unchanged.

---

## 17. Scope exclusions

This R4 authority does not authorize:

- `missing_fraction`;
- public method dispatch;
- public `compute_method`;
- unit conversion;
- counter reset inference;
- counter rollover inference;
- regression slope;
- interpolation;
- extrapolation;
- stream merging;
- segment selection;
- cross-segment arithmetic;
- current-support arithmetic for the three R4 methods;
- caller-supplied support;
- provider ranking;
- hidden conflict resolution;
- changes to R2 support binding;
- changes to S3 semantics.

---

## 18. Acceptance decision

Authority decision:

`R4_HISTORICAL_ARITHMETIC_AUTHORITY_CLARIFIED`

R4 is authorized to implement exactly:

1. exact within-segment endpoint delta;
2. exact source-observation-time counter endpoint rate;
3. exact historical endpoint slope using the configured historical clock.

All three computations operate only on already-authorized historical
support from one authoritative sufficient continuity segment.

No other R4 arithmetic semantics are authorized by this clarification.
