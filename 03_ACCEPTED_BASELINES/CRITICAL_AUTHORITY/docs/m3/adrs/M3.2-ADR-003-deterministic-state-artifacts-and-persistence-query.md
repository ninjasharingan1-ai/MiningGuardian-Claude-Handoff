# M3.2 ADR 003 — Deterministic State Artifacts and Persistence / Query Boundary

**Status:** ACCEPTED  
**Date:** 2026-09-20  
**Semantic decisions:** M, N, V  
**Acceptance:** ACCEPTED  
**Accepted by:** Human Owner  
**Acceptance date:** 2026-09-20

## Context

The frozen [M3 data contracts](../M3_DATA_CONTRACTS.md) and [runtime evidence contract](../M3_RUNTIME_EVIDENCE.md) distinguish raw observation authority from a derived current-state artifact. M3.1 separately persists canonical runtime observations and can restore acquisition cycles. The exact [M3.2 semantic-resolution report](../reviews/M3.2_SEMANTIC_CONTRACT_RESOLUTION_REPORT.md), sections 17–20 and 30–31, resolves deterministic content, production metadata, optional derived persistence, and bounded evidence retrieval. The [preflight](../reviews/M3.2_READ_ONLY_PREFLIGHT_REPORT.md) identified the missing operational boundary.

## Problem

Estimating state from a changing or truncated history, or estimating again during load, would make a stored artifact ambiguous. Conflating historical reference time with actual production time would falsely date replay output. A derived snapshot cannot replace the observations that support it.

## Decision

Separate three operations: `query_evidence` restores canonical M3.1 observations, an explicit `estimate` operation produces a new `EstimatedState`, and `load_state` restores a previously persisted state artifact **without running the estimator**. Estimation is deterministic in its semantic core for fixed inputs, configuration, reference time, and method/contracts versions. Production metadata lives in a distinct truthful envelope. Derived-state persistence is optional per operation, but when used it is immutable, complete, versioned, atomic, and separate from raw runtime evidence and M2 decision persistence. Evidence retrieval for normal estimation is bounded, filtered, stable, and reports incompleteness explicitly.

## Detailed Semantics

### Three operations and source authority

```text
query evidence  → restore canonical RuntimeObservation records
estimate explicitly → produce a new EstimatedState artifact
load state      → restore the exact previously persisted artifact
```

`load_state` MUST NOT run the estimator, fetch providers, reconstruct missing fields, or refresh quality/freshness. Persisted state is authoritative only as evidence of **what the identified estimator produced**. M3.1 `RuntimeObservation` remains raw evidence authority. Derived state never rewrites, supersedes, or impersonates the source measurement. M2 `DecisionEvaluationRepository` is neither a raw M3 runtime evidence store nor this derived-state owner. A loaded artifact can be inspected even if later raw input retrieval is unavailable; that does not permit re-estimation from missing evidence.

### Deterministic semantic content

For a fixed canonical observation set (including IDs, time, quality, identity, provenance, and metadata), fixed complete estimator configuration and subject mapping, fixed caller-supplied aware-UTC `state_reference_time`, and fixed method/contract/schema versions, the semantic `EstimatedState` content is fixed. This includes selected/excluded evidence references and reasons, field values and assessments, confidence and uncertainty, conflicts, limitations, temporal basis, snapshot summary, and semantic content identity. Deterministic ordering is explicit.

The deterministic core does not consult hidden wall time, randomness, external provider fetches, mutable registry state, process-local continuity caches, or unordered iteration. Provider acquisition precedes estimation and enters only as canonical evidence. Method identity/version, relevant field-contract version, configuration/parameter fingerprint or retained immutable parameter set, schema version, and input-manifest identity make replays reproducible. Unknown versions fail explicitly; a mutable `latest` alias does not define a replay. No general ML model registry is introduced.

### Semantic content versus production envelope

`state_reference_time` is the current-state instant under ADR 002. `estimated_at` truthfully records when this particular artifact was produced. Historical replay performed later must not claim that its output was produced at historical `T`. Explicit production metadata supplies `estimated_at` and a distinct artifact identity. Two estimates over the same fixed semantic inputs can have the same semantic content identity while different production artifact identities and `estimated_at` values. Full artifact equality requires an identical production envelope as well as identical semantic content. A stable semantic content identity must not silently ignore a semantically relevant input or configuration difference.

### Optional derived-state persistence

An estimate can be reconstructed on explicit request from a complete fixed evidence set. If persistence is requested, save the **complete** state snapshot atomically in an additive, separate derived-state boundary: all fields and requested scope; validity, confidence, uncertainty, conflicts, limitations and completeness; source observation IDs and input dispositions; temporal/reference data; method and field-contract identities/versions; configuration and schema versions; semantic content identity; and production metadata. Load must restore these exact recorded semantics without rerunning estimation. Do not persist a partial transaction as a successful state.

Reusing the same production artifact identity with identical bytes is idempotent. The same artifact identity with different bytes is an **INTEGRITY ERROR**. A correction creates a new immutable artifact with an explicit supersession reference; it does not update an old derived artifact in place. Unsupported schema or corrupted payload fails safely and visibly. If an estimate is not saved or a write fails, the result is explicitly unsaved; it is not reported as persisted. This ADR chooses no table design, migration mechanism, or database engine and changes no frozen M3.1 table.

### Bounded, stable evidence-query contract

Normal estimation requires a finite start/end interval with an explicit time basis, an as-of availability cutoff, Guardian-session selection (including explicit null/all semantics), source and source-instance selection, signal selection, subject/workload scope where available, maximum records, maximum decoded bytes, a stable dataset snapshot or watermark, deterministic continuation if paginated, and bounded continuity-predecessor lookup. The query exposes completeness and integrity status. A fixed query and stable watermark return the same evidence set in deterministic transport order; a caller must not unknowingly combine pages from changing datasets.

The query includes potentially invalid, stale, reset, missing, conflicting, and unavailable-source evidence needed to assess a field; it is not a query of only “good” records. Null source recording time remains null and is not silently replaced by receipt time. Transport ordering is deterministic for retrieval, not proof of source-event order. A resource limit or truncated page must be reported as incomplete rather than labeled complete. Estimation requiring the missing records returns `UNKNOWN` for affected fields under ADR 001 or a typed operation failure when the complete input set cannot be established; it must not silently estimate from a truncated set. No unbounded full-history scan is the normal path. A bounded predecessor cannot authorize a cross-segment delta under ADR 002.

## Invariants

Fixed semantic inputs produce fixed semantic content. `estimated_at` is production time, not `state_reference_time`. `load_state` performs record restoration, never computation. Raw M3.1 observation authority remains separate from derived state. State artifact identity cannot alias different bytes. Query truncation cannot masquerade as a complete evidence set. No state artifact confers prediction, reward, policy, or execution authority.

## Rejected Alternatives

Persistence-only estimation; mandatory persistence for every estimate; load-time recomputation; hidden wall-clock production or historical backdating; mutable `latest` methods; process-local continuity as replay authority; raw-observation replacement; M2 decision-table reuse; unbounded normal scans; silent query truncation; receipt-time fallback for null source time; filtering out all adverse evidence; and pagination over a changing evidence set.

## Consequences

The handoff needs explicit versioned estimator and field contracts, a complete input manifest, reproducible retrieval, and distinct semantic-content and production identities. Optional saving increases storage and integrity obligations but does not alter raw evidence. Storage failures are explicit. Replays can compare semantic content across production runs while retaining truthful production history.

## Compatibility

This ADR does not modify M2 Evidence → Claim → Hypothesis → Candidate semantics; ADR-0006 scoring; `DecisionPolicy`, `DecisionScorer`, or `DecisionRanker` ownership; M2 Prediction or DecisionConfidence semantics; M2 persistence reconstruction; M3.1 `RuntimeObservation`, timestamp, quality, freshness, or runtime-evidence authority; or the M2/M3 no-execution boundary. The frozen M3.0 ownership split remains intact. ADRs 001 and 002 define field assessment and temporal admission; this ADR records/restores their results.

## Persistence Impact

An additive derived-state owner records complete immutable versioned snapshots with atomic writes, integrity validation, and explicit supersession. It does not use M2 decision persistence or mutate M3.1 raw runtime tables. Loading preserves the saved schema, method, configuration, inputs, all field-level assessments, and production envelope. Same-ID/different-bytes is an integrity failure, not an upsert correction.

## Observability / Evidence Impact

Every non-null derived value identifies its supporting canonical observation IDs. Selected, excluded, and conflicting input dispositions remain traceable. Stable bounded query results and their watermark are part of the reproducibility evidence. Source-provided times and qualities survive retrieval unchanged. Querying evidence does not itself estimate state.

## Verification Requirements

Future tests must cover deterministic replay with shuffled retrieval order; same semantic content with distinct production envelopes; accurate historical replay `estimated_at`; exact persisted round-trip; proof that `load_state` never invokes the estimator or provider; atomic rollback; same-ID/different-bytes rejection; corruption and unsupported schema; explicit supersession; source/time/session/subject filters; null source time; stable paginated retrieval and watermark change; query truncation and record/decoded-byte budget exhaustion; bounded predecessor handling; and inclusion of adverse evidence. No implementation tests run during ADR drafting.

## Security / Trust Implications

Future implementation must test poisoned observations, mutable configuration or method substitution, corrupted stored artifacts, forged input references, unstable pagination, malformed metadata, resource exhaustion, and deliberate suppression of conflicts or adverse quality. Content digests detect accidental drift but are not proof of source authenticity. This ADR grants no execution authority.

## Implementation Boundary

This ADR does not authorize M3.2 implementation by itself.

Implementation begins only after:
1. all required M3.2 ADRs are ACCEPTED;
2. ADR acceptance closure and integrity verification are complete;
3. `M3.2_IMPLEMENTATION_HANDOFF` is prepared;
4. implementation is explicitly authorized.

## Supersession

None. This ADR operationalizes frozen M3.0 reconstruction and persistence boundaries; it does not supersede frozen M2, M3.0, or M3.1 authority.
