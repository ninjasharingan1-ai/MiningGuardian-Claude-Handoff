## 4. Canonical Observation Contract

`RuntimeObservation` stores UUID observation/acquisition identities, source and
nullable source instance, signal/value/unit, source event/recording/receipt times,
optional processing time, primary quality plus secondary conditions/metadata,
freshness, nullable Guardian session, provenance, and the explicit
`m3.1.runtime-observation.v1` schema version. Serialization rejects non-finite
canonical values, including nested values. Unknown fields and unsupported schema
versions are rejected. No database row ID is a domain identity.

## 5. Time Semantics

`observation_time` means source recording time. `ingestion_time` means Guardian
receipt time. Missing source clocks remain null. Optional event time is not
duplicated from recording time. New authoritative timestamps reject naive values
and normalize aware values to UTC. In-process durations use monotonic clocks.
Future/inconsistent clock order becomes OUT_OF_RANGE; it is not clamped to fresh.
Historical M2 timestamp behavior and `timestamp_iso` are unchanged.

## 6. Quality Semantics

Primary precedence follows handoff section 16 exactly:

`CORRUPTED > SOURCE_UNAVAILABLE > OUT_OF_RANGE > RESET_OR_DISCONTINUOUS >
OUT_OF_ORDER > DUPLICATED > DELAYED > STALE > MISSING > UNKNOWN > VALID`.

Secondary conditions remain available. Zero is preserved. Numeric measurements
are finite; utilization is within 0–100, temperatures cannot be below absolute
zero, and nonnegative physical quantities/counters cannot be negative. Integer
counters reject fractions and values outside the implementation's signed-64-bit
representation budget; NVML throttle masks allow unsigned 64-bit values. Raw
invalid numeric evidence is retained diagnostically, never as a valid number.

## 7. Freshness Semantics

`FreshnessRule` is configurable per source and exact signal. No universal default
threshold is applied. `RUNTIME_FRESHNESS_RULES` accepts the Settings JSON form, for
example a list with source `NVML`, signal `temperature_c`, and
`stale_after_seconds: 30`. A configured rule does not manufacture a source clock:
NVML and the repository's current miner fixture still have UNKNOWN source age.
Receipt age remains explicit. STALE uses source recording age; DELAYED requires
explicit event timing under handoff section 19. The M2 FreshnessPolicy is unchanged.

## 8. Source / Provenance Model

Sources are NVML, SRBMINER_HTTP, POOL_DATA_FROM_MINER, and OBSERVER. Hardware
identity prefers source-provided UUID, then PCI identity. Missing identity remains
null. Miner endpoint identity does not prove a process incarnation. One redacted
raw miner payload per cycle retains rig/worker/device/pool metadata; promoted
signals reference its observation UUID. Known secret keys and endpoint
credentials/query parameters are redacted. Redaction is recorded in provenance.
Source identity is attribution, not cryptographic authentication.

## 9. Correlation Model

`AcquisitionContext` creates one UUID per actual collection cycle and receives its
Guardian session explicitly. Adapter records must match that context. Correlation
does not assert causality, physical GPU mapping, or miner PID. Counter continuity
requires explicit stream scope; share counters use miner workload ID plus raw
algorithm context when supplied. No ID is inferred from list position. Uptime
drops are discontinuities, not proof of restart. Duplicate detection requires
stable source event identity; equal values alone never qualify. History retains
at most 1,024 streams and 64 event identities per stream, in process only.

## 10. NVML Changes

`NVMLObserver` uses only getters through an injected binding. It isolates metric
failures, retains capability states, preserves throttle zero, validates values,
and records receipt time per read. Definitively unsupported calls are suppressed
in a bounded per-observer cache. When identity is unavailable, index-based cache
keys are only retry-suppression keys, never persisted GPU identities. Handle
failure clears caches. An observer restart permits reprobe. No physical NVML-to-
miner device mapping is asserted.

## 11. SRBMiner Changes

`MinerObserver` performs one GET per acquisition, disables environment proxies and
redirects, applies an overall request timeout, limits the response to 1 MiB, rejects
duplicate JSON keys, and rejects compressed responses before decompression.
JSON structure limits are 20,000 nodes, depth 16, and 16,384 characters per string.
Malformed workloads produce explicit records while valid workloads survive.
Existing H/s conversion, multi-workload parsing, and registry IDs remain intact.
API availability is not mining health. No undocumented source clock is inferred.

## 12. Pool/Network Observation Changes

Pool endpoint identity is promoted from the explicit miner field. Connection time,
uptime, difficulty, last-job field, and latency retain raw values with UNKNOWN
interpretation where the repository does not establish units/timing. In particular,
latency zero is not labeled milliseconds and last_job_received 21 is not labeled
seconds. No new pool API, network scanning, or independent pool-health claim exists.

## 13. Runtime Evidence Persistence

`RuntimeEvidenceRepository` owns two additive tables:
`m3_runtime_cycles_v1` and `m3_runtime_observations_v1`. Explicit installation checks
existing columns, type affinity, primary keys, and stored schema versions; it does
not alter M2 tables or use create_all as a migration framework. One cycle is atomic
on a repository-owned connection. Exceptions roll back and release the connection.
UUIDs, all times, quality, values, freshness inputs/results, and provenance round
trip through versioned JSON. SHA-256 checks detect accidental payload corruption.
An indexed correlation lookup restores records without rerunning cognition.

Writes are bounded to 10,000 records / 16 MiB serialized payload per cycle. The
configurable `RUNTIME_MAX_DATABASE_BYTES` default is 1 GiB. SQLite page usage plus
a conservative incoming payload allowance determines write admission. This is
an admission budget, not a filesystem quota; it never deletes history and does
not govern existing legacy writers or unrelated database users.

## 14. Fault Isolation

Miner and GPU collection failures are independent. Canonical storage precedes
legacy sample storage. Storage errors produce structured records and diagnostics;
failed telemetry is explicitly unsaved. One pending failure diagnostic is retained
and represented on recovery, with original failure identity/time references. There
is no unbounded retry/spool buffer and no claim that lost evidence was stored.
Fresh connections avoid poisoned ORM-session reuse; legacy failures explicitly
roll back their own session.

## 15. Legacy Compatibility

Miner snapshots project through existing registry/sample semantics without another
network acquisition. Canonical hardware projects one way through
`legacy_hardware()`. Its receipt timestamp converts explicitly to the existing
local-naive representation; canonical UTC evidence remains intact. M2 world state
and historical rows are not rewritten. Legacy sample storage remains non-atomic
across its existing repositories; M3 cycle atomicity is separate.

## 25. Known Limitations

Real hardware and sustained production validation remain outstanding. Native NVML
driver stalls cannot be forcibly timed out by this synchronous getter boundary.
Source clocks, process incarnation, and cross-source GPU mapping remain unknown
when not supplied/proven. Duplicate detection is unavailable for current sources
without stable event IDs. Capability caches are process-local. Canonical freshness
defaults to UNKNOWN rather than inferring age from receipt. Failed-cycle telemetry
is not replayed from an unbounded spool. The final cycle's completed storage/cycle
duration remains in diagnostics/result unless another cycle occurs.

## 27. Residual Security Risks

An API/driver can lie consistently; provenance does not authenticate the source.
Checksums cannot protect against an administrator who changes both payload and
digest. Redaction covers identified secret keys and endpoint credentials, not
arbitrary secrets deliberately embedded in otherwise ordinary telemetry strings.
The storage admission budget is not an OS quota and does not constrain legacy
writers. Native driver hangs and real-machine scheduling/IO impact require
operational validation. None of these permits control or promotes unknown values
to verified health, prediction, or authorization.
