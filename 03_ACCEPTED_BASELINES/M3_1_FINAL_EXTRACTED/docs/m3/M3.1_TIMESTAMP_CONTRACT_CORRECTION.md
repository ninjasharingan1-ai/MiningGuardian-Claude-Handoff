# M3.1 Timestamp Contract Correction

## Status

```text
Correction type: HANDOFF ALIGNMENT
Frozen M3.0 architecture changed: NO
Superseding ADR required: NO
Reason: The M3.1 handoff contained timestamp definitions that conflicted with the already frozen M3.0 glossary.
```

## Authoritative frozen semantics

```text
observation_time = when the source recorded the observation
ingestion_time = when MiningGuardian received the observation
```

## M3.1 implementation rule

```text
event_time
```

is optional and may be populated only when the source explicitly provides a distinct underlying-event time.

If MiningGuardian needs to record canonical transformation/runtime-layer entry time, use an additional implementation-level timestamp such as:

```text
processing_time
```

or:

```text
canonicalization_time
```

Do not redefine `ingestion_time`.

## Resolution

The M3.1 handoff and Codex implementation prompt were corrected to restore alignment with the frozen M3.0 glossary.

This correction does not modify any frozen M3.0 canonical document.
