3. CANONICAL PROJECT OBJECTIVE
======================================================================

MiningGuardian has one primary optimization North Star:

MAXIMIZE REALIZED MINING REWARD PER REAL-TIME EVALUATION BLOCK

subject to:

- hard GPU safety constraints;
- mining continuity;
- operational stability;
- evidence sufficiency;
- hardware/capability constraints;
- bounded and reversible execution authority.

This objective must remain explicit throughout future architecture.

MiningGuardian is NOT fundamentally optimizing:

- maximum reported hashrate;
- maximum GPU clocks;
- minimum temperature;
- minimum power;
- maximum TH/W;
- share count;
- predicted reward alone.

Those are state variables, evidence, constraints, features, diagnostics, or intermediate optimization signals.

The final optimization criterion is sustainable realized mining reward over actual elapsed real time.

Conceptually:

RealizedRewardRate = RealizedReward / ActualElapsedEvaluationTime

Exact accounting semantics must eventually be governed by an accepted versioned RewardContract.

A theoretically faster configuration is not necessarily superior if restart, warm-up, reconnect, stale shares, instability, or other transition costs reduce realized reward within the real-time evaluation block.

NO_ACTION must always remain a valid alternative.

Hard safety dominates reward optimization.
